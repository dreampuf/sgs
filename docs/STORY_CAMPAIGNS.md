# 剧情战役

剧情模式不再是附带序章文案的随机身份局。它由四层数据组成：

```text
阵营战役 StoryCampaign
  -> 年代事件表 timeline
    -> 场景 StoryScenario
      -> 座次/人物、主题牌池、战中事件、目标、解锁内容
```

每个场景都声明：

- 年代、地点、序章、目标与胜败文本；
- 本地可选武将、固定参战武将与身份座次；
- 必需扩展包与主题牌名集合；
- 按回合触发的战中叙事节点；
- 胜利后解锁的武将和下一场景。

## 进度与存档

阵营进度使用 `sgs.story-progress.v1.<faction>` 独立保存。单局存档同时记录
`campaignId`、`scenarioId`、已完成场景和已解锁武将，因此刷新后可以恢复到同一场战斗；场景胜利后才会开放年代表中的下一事件。

旧的无剧情存档继续按原 schema 读取，`campaign` 字段是可选的。

## 扩展场景的规则

新增场景应加入 `src/session/story-campaign.ts`，并满足以下门禁：

1. 年份在阵营时间线内单调递增。
2. 所有参战和解锁武将必须由场景声明的扩展包提供。
3. 主题牌池至少能发完所有起始手牌，并保留一张摸牌。
4. 本地可选武将必须已经由之前的场景解锁。
5. 至少有一个战中叙事节点，不能只提供开场文字。

当前场景的结局仍建立在 Core 身份胜负之上，但人物、阵营座次和目标被脚本固定。
后续增加护送、限时、防守、指定角色撤离等非身份胜负时，应把条件实现为 Core
场景目标解析器，不能只在 UI 结算时改写“胜利”文本。
