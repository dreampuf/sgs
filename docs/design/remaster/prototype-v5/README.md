# v5 密度原型

这个原型不再用生成效果图判断布局。它直接使用现有英雄与卡牌素材，通过真实 HTML/CSS 验证桌面、平板和手机上的容量、溢出与区域尺寸。

## 对比结果

1280×720 浏览器中的当前游戏使用固定 1000×620 舞台，只覆盖约 67.3% 的视口面积。v5 使用完整 `100dvw × 100dvh`，但没有把 UI 元素随视口等比放大。

| 项目 | 当前界面 | v5 原型 | 结论 |
| --- | ---: | ---: | --- |
| 游戏根区域 | 1000×620 | 1280×720 | 扩展的是舞台，不是组件 |
| 顶部工具栏 | 29px | 32px | 基本保持当前密度 |
| 单个其他玩家 | 131×152 | 最大 180×122 | 更宽以容纳状态，但更矮 |
| 本地底栏 | 1002×148 | 1272×151 | 高度几乎不变，横向容量增加 |
| 本地英雄 | 113×106 | 最大 132×146 | 不再使用 v4 的大型半身立绘 |
| 手牌可用宽度 | 570px | 922px | 1280px 下直接显示 8 张 96px 手牌 |

中央舞台是牌、目标线、判定和动画的临时空间，不算 UI 占位。空闲时保持安静；出现事件时只在事件附近增加信息，不放常驻侧栏或巨型人物。

## 响应式结果

- 1280×720：工具栏 32px、对手区 122px、底栏 151px、中央舞台 394px；无页面滚动。
- 820×1180：其他玩家仍保持紧凑上排，底栏只增加到适合触控的高度。
- 390×844：对手区 94px、中央舞台 482px、底栏 214px；8 张牌均保留在横向手牌层中，无页面溢出。

## 20 人场景

访问 `?players=20` 会渲染本地玩家以外的 19 个真实座位节点，而不是复制一张截图：

- 1280×720：19 个对手按 10+9 两排排列，每个座位 122×64px；对手区总高 132px，中央舞台仍有 385px，本地底栏保持 151px。
- 820×1180：使用两排横向座位轨道，单个座位 104×60px；轨道可水平滚动，不压缩中央舞台。
- 390×844：使用一排 92×64px 横向轨道，19 个座位均保留在 DOM 中；轨道宽 1802px，可滚动访问。
- 紧凑座位常驻显示头像、姓名、阵营、身份、血量和手牌数。点击或键盘确认后，在中央舞台显示技能、装备和判定区详情。

## 运行

在仓库根目录运行：

```sh
npm run serve
```

然后访问：

```text
http://127.0.0.1:8080/docs/design/remaster/prototype-v5/
```

20 人场景：

```text
http://127.0.0.1:8080/docs/design/remaster/prototype-v5/?players=20
```

## 进入生产 UI 前的约束

- 玩家框采用内容驱动的最大尺寸，玩家少时不能横向拉满。
- 本地底栏在桌面 720px 高度下不得超过 154px。
- 卡牌宽度保持 68–96px；牌多时先增加重叠，再启用横向滚动，不整体缩小文字。
- 英雄、装备、操作区使用封顶宽度，把增长空间优先留给手牌。
- 装备继续采用当前界面约 142×25px 的窄横条：小图标、名称、距离或状态；不渲染为卡牌缩略图。
- 8–20 人局使用多排紧凑座位或可聚焦座位轨道，不能放大单个座位填充空间。
- 背景与中央舞台可以扩展；常驻 UI 不随屏幕等比放大。
