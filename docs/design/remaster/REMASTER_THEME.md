# 三国杀 Remastered 主题：山河铸印

版本：`remaster-theme-v5`

“山河铸印”不是给旧素材统一加一层高清滤镜，而是重建一套覆盖英雄、卡牌、技能、战场和交互状态的视觉语言：人物像史诗群像，卡牌像战场瞬间，技能像军令与印记，界面采用现代编辑设计组织水墨、人物和信息，不再依赖成套仿古边框制造历史感。

## 视觉母版

- [人物与组件风格板 v2](./shanhe-zhuyin-styleboard-v2.png)
- [现代水墨暗场界面 v4](./shanhe-zhuyin-modern-ink-dark-v4.png)
- [现代水墨明场界面 v4](./shanhe-zhuyin-modern-ink-light-v4.png)
- [可运行的响应式密度原型 v5](./prototype-v5/README.md)

v4 只保留色彩、材质和无边框信息层方向，不再作为尺寸基准。v5 的真实 HTML/CSS 原型是布局与容量基准；明场稿只用于验证同一组件在白昼剧情背景上的可读性，不是另一套 UI。

生成图只约束色彩、材质和视觉层级，不再用于决定组件尺寸。文字、数字、花色、规则描述和状态必须由代码渲染。v1 因人物脸谱化和电子游戏 HUD 倾向被淘汰；v2 因过度拟物和布局松散被淘汰；v3 因旧页游式视觉被淘汰；v4 建立现代编辑式水墨语言，但仍把人物和卡牌放得过大。v5 以当前界面实测尺寸为基线，只扩展舞台和手牌容量，不让常驻 UI 随屏幕等比放大。

| 神话再临英雄卡 | 24 | 200×290 | 与标准包尺寸和画风不同 |

当前内容规模为 49 名英雄、43 张卡牌、83 个技能。Remastered 的目标不是制造 175 套互不相关的装饰，而是让这些内容共享少量、明确、可验证的视觉规则。

## 核心设计语法

1. **英雄是具体的历史人物**：先定义年龄、脸型、社会经历、身体状态、神态和姿势，再处理服饰；阵营色不能替代人物塑造。采用克制的写实水墨，不走脸谱、二次元、写真 cosplay 或西式奇幻路线。
2. **卡牌是战场瞬间**：每张牌先用动作或物件形成清晰剪影，在 72px 宽时仍能辨认；卡名、点数、花色和规则不进入生成图。
3. **技能是军令与印记**：技能标签采用方正印章语汇，通过形状、纹理和动效表达类型与状态，不为 83 个技能分别生成一枚不可维护的图标。
4. **界面是一块连续的数字牌局空间**：保留玩家、牌堆、弃牌、装备区和手牌之间的牌桌拓扑，但不要求模拟真实桌面。用比例、透明度、对齐和景深建立层级，不用方框包住每一项信息。任何长期占据的区域都必须显示状态、承载操作或为当前动画服务。

界面分成四层，并保持独立：

- **战场层**：阵营或剧情场景背景，可替换、低对比、无交互。
- **内容层**：英雄母图、卡牌插画、装备和判定牌。
- **规则层**：名称、花色、点数、距离、血量、目标与技能状态，全部由代码渲染。
- **交互层**：选择、高亮、拖拽、提示、响应窗口和动画，只由当前游戏状态驱动。

## 色彩与材质

| 语义 | 主色 | 使用方式 |
| --- | --- | --- |
| 基础暗色 | `#0A1118` / `#1A2732` | 夜战背景、半透明墨色层、暗场文字衬底 |
| 基础明色 | `#F4F0E7` / `#E9E1D2` | 明场背景、卡面和高对比内容层 |
| 魏 | `#477FAE` | 仅用于阵营印记和细小边缘状态 |
| 蜀 | `#668A50` | 仅用于阵营印记和细小边缘状态 |
| 吴 | `#B64D42` | 仅用于阵营印记和细小边缘状态 |
| 群 | `#9A7A42` + `#34302A` | 旧金或炭黑阵营印记，不使用吴国朱红 |
| 行动焦点 | `#B6493A` | 选中牌、主操作与目标墨线 |
| 生命/恢复 | `#63A06F` | 血量、恢复与正向状态 |
| 稀有高光 | `#D4B06A` | 少量使用，不形成满屏金边 |

阵营不能只依赖颜色：魏使用锐角金属纹，蜀使用编织与木纹，吴使用漆面和浪纹，群使用裂土与旧金纹。危险状态还需要形状、图标或脉冲，不能只变红。

### 明暗场适配

暗场和明场不是两套组件，只是同一组件系统在不同剧情背景上的对比度探针。运行时读取背景亮度，为人物文字、卡牌和操作区自动选择深色或浅色衬底；衬底仅覆盖内容局部，不铺成大块面板。卡牌永远是当前画面中对比最高的对象，选中牌再通过抬升、朱砂细边和阴影获得一级强调。

### UI 造型禁区

- 禁止全屏深褐或泛黄滤镜；历史感不能等于“所有东西都变旧”。
- 禁止粗金边、雕花角、斜面按钮、皮革和木框组成的伪古风套件。
- 禁止每条状态都放入独立矩形框；优先使用基线、留白、字号和透明度分组。
- 禁止大面积低对比纹理与小字叠加；背景纹理必须在信息区域自动减弱。
- 禁止英雄立绘都使用相同肩宽、三分之二侧脸和严肃胡须模板。

## 英雄资产契约

每位英雄只生成一张无边框、高分辨率的 3:4 或 4:5 半身母图，再由代码和构建工具派生英雄卡、座位头像、移动端头像和剧情立绘。不得继续为同一英雄独立绘制大头像、小头像和英雄卡。

每张母图必须保存：

- `focusX`、`focusY`：响应式裁切焦点；
- 面部安全区和头顶至少 8% 留白；
- 武器朝向、超出安全区的方向；
- 阵营、年代、服饰依据和场景标签；
- 主题版本、完整提示词、生成批次与选择理由。

统一约束：主光从左前上方进入，暖金只作边缘高光；衣甲参考东汉末年并允许有限的戏剧化，但禁止西式板甲、霓虹科技和夸张手游塑料质感。肤色保持自然，阵营色不得照到脸上或覆盖整套服装。每名英雄必须有不同的年龄、头骨轮廓、体型、发际线、胡须形态和重心姿势；禁止批量生成“同一张严肃男性脸换衣服”。

第一批校准只做曹操、刘备、孙权、张角四人。四张并排仍像同一作品后，才批量生成其余 45 人。

## 卡牌资产契约

43 张卡牌各有一张无边框事件或物件母图，卡框、卡名、点数、花色、规则、包标识和稀有度均由代码组合。

- 基本牌：单一动作，轮廓强，背景简洁。
- 锦囊牌：表现局势变化，允许更宽的叙事镜头。
- 延时锦囊：留出判定印记区，构图带悬念和时间感。
- 装备牌：物件为中心，材质与轮廓优先，减少人物遮挡。

首批校准为：杀、闪、桃、无懈可击、闪电、丈八蛇矛。它们覆盖动作、防御、恢复、响应、判定和装备六种视觉问题。

## 技能视觉系统

83 个技能继续以文字为核心，使用共享的语义印记：主动、触发、锁定、转换、主公、限定。技能状态不能只靠颜色区分：

| 状态 | 视觉行为 |
| --- | --- |
| 可用 | 实边、轻微呼吸高光，可点击 |
| 已选择 | 金属边明亮，印面轻压入，显示当前步骤 |
| 选择材料 | 左侧切口或牌形槽，提示“选牌” |
| 选择目标 | 右侧箭头或人物槽，提示“选目标” |
| 本回合已用 | 印泥变淡，仍可读但不可点击 |
| 条件不满足 | 降低材质对比，并给出可访问的禁用原因 |

技能说明使用悬停、长按或聚焦浮层；手机端用底部抽屉，不依赖 hover。

## 全屏响应式战场

根容器使用 `100dvw × 100dvh`，同时处理安全区和浏览器动态工具栏。禁止用全局 `transform: scale()` 缩放固定舞台；布局应根据可用空间重排。

所有尺寸都保持当前实机布局的拓扑：其他玩家在桌面远端，本地玩家托盘固定在近端，牌堆与弃牌成组位于桌面右侧，中央是可见的空桌面。响应式只压缩、滚动或折叠这些区域，不改变它们之间的空间含义。

### 密度预算

- 使用 8px 基线网格；组件内部间距 4–8px，主要区域之间不超过 12px。
- 游戏画面直接接触视口四边，不设置设备框、厚桌边或装饰性外边距。
- 顶部工具栏以 32px 为基准；低频功能收入一个菜单。
- 桌面对手区使用 `clamp(108px, 17dvh, 128px)`，本地区使用 `clamp(136px, 21dvh, 154px)`；两者都有上限，额外高度全部交给中央舞台。
- 中央舞台是事件、判定、目标线与动画的弹性空间，不算常驻 UI 占位。空闲时允许保持安静，事件发生时只在事件附近增加信息。
- 手牌区获得底栏扣除装备、操作和英雄后的全部剩余宽度；嵌套容器不得重复添加 padding。

### 桌面：宽度 ≥ 1024px

- 其他玩家框采用内容驱动尺寸，单个桌面座位最大 180×128px；玩家少时不横向拉满，玩家多时增加座位而不是放大已有座位。
- 牌堆和弃牌位于右中；装备、延时区、手牌、操作盘和当前英雄组成一条完整底部托盘。
- 本地装备沿用当前约 142×25px 的窄横条，依次显示小图标、装备名和距离/状态；不得渲染成卡牌缩略图或大图标宫格。
- 操作按钮紧邻当前选择，常驻最多三个主要动作，不使用占地巨大的圆形操作盘。
- 20 人模式为 19 个对手提供真实座位节点：桌面采用 10+9 两排 122×64px 紧凑座位；常驻显示头像、姓名、阵营、身份、血量和手牌数，技能、装备与判定区通过聚焦详情查看。不能用一张汇总图或不可查询的重叠头像代替。

### 平板：600–1023px

- 其他玩家进入紧凑顶部轨道；20 人局使用两排 104×60px 横向滚动轨道。牌堆、弃牌和中央交互区仍保持原有相对关系。
- 底部托盘保持连续，装备仍使用窄横条并允许名称省略，操作盘与英雄区仍位于手牌右侧。
- 手牌触控宽度不低于 72px，拖动和点击都可完成选择。

### 手机：小于 600px

- 顶部为可横向滚动的小型玩家板；20 人局使用单排 92×64px 轨道，点击座位后在舞台上方打开详情。中部为当前事件区，容纳牌堆、弃牌、目标关系和判定状态。
- 本地英雄形成紧凑横带，手牌在其下方横向滚动；装备和延时区从底部托盘标签展开。
- 出牌、技能和结束阶段固定在安全区之上；详情、装备和技能解释使用底部抽屉。
- 所有触控目标至少 44×44px，不让牌名或技能说明承担唯一点击区域。

横屏手机使用平板的紧凑变体；竖屏平板仍使用平板信息架构，不简单放大手机布局。

## 字体、间距与动效

- 英雄名、牌名和章节标题使用宋体或楷体气质的展示字体；控制和说明使用现代无衬线；点数与计数使用等宽数字。
- 间距级别固定为 4、8、12、16、24、32、48px。
- 动效时长固定为 120、220、360、650ms，分别对应反馈、状态切换、牌移动和章节级转场。
- 所有动效由领域事件驱动，并可投影成 JSONL 视觉序列；`prefers-reduced-motion` 下保留状态变化、去除位移和闪烁。

## 生成与追溯

每个生成资产必须记录：内容 ID、完整提示词、主题版本、原始输出、入选版本、运行时裁切、焦点元数据、审核结论和淘汰原因。禁止覆盖旧版本。

建议目录：

```text
assets/remaster-v5/
  source/heroes/<hero-id>/
  source/cards/<card-id>/
  source/backgrounds/<scene-id>/
  selected/
  runtime/
  manifests/
```

旧主题继续存在，运行时通过 `remaster-theme-v5` 显式选择新资源；确认全量覆盖后再切换默认主题。

## 分批落地

1. **纵向切片**：四阵营英雄各一人、六类卡牌、六类技能印记和三端战场壳。
2. **标准包**：补齐其余标准英雄和卡牌，并完成小尺寸识别测试。
3. **神话再临**：补齐 24 名英雄和 11 张扩展卡，不再保留独立尺寸体系。
4. **完整战场**：重做玩家座位、响应窗口、判定区、装备区、技能选择和结算面板。
5. **场景与效果**：为首页、常规局和阵营剧情提供可替换背景，增加受控粒子与镜头转场。
6. **默认切换**：视觉回归、性能预算和可访问性通过后，将新主题设为默认。

## 验收标准

- 四阵营即使转为灰度，也能通过纹理和轮廓区分。
- 每位英雄只有一张母图，所有设备裁切均来自同一来源。
- 每张卡在 72px 宽时仍能通过主轮廓识别。
- 技能类型和状态不以颜色作为唯一线索。
- 360×800、768×1024、1024×768、1366×768、1920×1080 下均无关键操作溢出。
- 移动端触控目标至少 44px；安全区不遮挡出牌和结束阶段按钮。
- 20 人局座位不相互覆盖，玩家状态仍可查询。
- 高分辨率素材按需加载，不阻塞首屏。
- Remastered 不改变 Core、`LegalAction` 或 JSONL 事件合同；主题只消费确定性状态。
