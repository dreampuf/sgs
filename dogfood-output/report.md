## 已修复问题

### DG-01：没有可用响应牌时对局无意义停住

- 严重级别：High
- 复现：手里没有“无懈可击”时使用“无中生有”或“火攻”；所有手牌变灰，对局必须手动点击无说明的“取消”才继续。铁索连环的两个目标会重复停两次。
- 根因：Core 正确生成了只含 `pass` 的响应决策，但浏览器适配器仍把它展示给真人玩家。
- 修复：真人的 `respond-card` 决策若唯一合法动作是 `pass`，适配器直接提交，不再打断玩家。
- 回归：`没有可用响应牌时自动放弃，不用玩家反复点击取消`。

### DG-02：火攻选牌后产生幽灵手牌

- 严重级别：High
- 复现：火攻要求弃置同花色牌时选择“朱雀羽扇”；Core 已把牌移入弃牌堆，但手牌区仍保留灰色羽扇。后续“闪”和弃牌也可能继续残留。
- 根因：选择框把同一个卡牌模型重新绑定到临时 `.choose_card`，覆盖了原手牌 DOM 的主绑定；结算动画随后删除临时节点，而不是原手牌。
- 修复：新增临时预览绑定，只建立 DOM→卡牌的反向关系，不覆盖卡牌→主 DOM；解绑也只删除与目标 DOM 一致的主绑定。
- 回归：`选择框使用临时卡牌绑定，火攻弃牌后不会留下幽灵手牌`。
- 截图：`screenshots/bug-phantom-discarded-card.png`。

### DG-03：仁德等非摸牌移动不会显示到手牌区

- 严重级别：High
- 复现：AI 刘备连续用仁德交给玩家 6 张牌；Core、玩家模型均为 12 张，页面只显示原手牌和摸到的 6 张。
- 根因：动画层只为 `reason=draw` 的入手牌事件创建 DOM，遗漏给予、获得、顺手牵羊等其他合法手牌区移动。
- 修复：每次 Core 命令结算后执行通用手牌一致性同步，补齐缺失 DOM、删除已离开手牌区的节点，并让 AI 手牌计数以 Core 投影为准。
- 回归：`给予等非摸牌移动后，手牌模型与玩家可见卡牌保持一致`。

### DG-04：决策框泄漏内部英文 reason

- 严重级别：Medium
- 复现：火攻弃牌弹框标题显示 `fire-attack-discard`，玩家无法直接理解操作目的。
- 修复：将标准牌、装备和已迁移武将技能的决策 reason 映射为中文玩家指令；未知 reason 使用安全的“请选择”，不泄漏内部标识。
- 截图：`screenshots/live-fire-attack-choice.png`。

### DG-05：缺少当前操作指引，零弃牌提示会残留

- 严重级别：Medium
- 复现：出牌、响应、弃牌阶段只靠图形按钮猜测；无需弃牌时一度显示“请选择 0 张手牌”，AI 决策框出现后仍残留。
- 修复：增加出牌、响应、目标和弃牌数量提示；零弃牌直接清空；任何决策弹框会接管并清除旧提示。
- 回归：`无需弃牌时直接结束回合，不留下选择零张牌的旧提示`。

### DG-06：页面下半部出现突兀白底，关键控件和卡牌缺少可访问名称

- 严重级别：Low
- 复现：高窗口中 1000×620 固定桌面下方是大块白色；浏览器可访问树只能看到无名 `generic`/`image`。
- 修复：页面空余区域沿用桌面纹理底色；开始、确定、取消、弃牌、选将和手牌提供玩家可读名称。
- 截图：`screenshots/live-initial.png`、`screenshots/regression-initial.png`。

### DG-07：过河拆桥泄露目标手牌并造成“追加己方牌”的交互误解

- 严重级别：High
- 复现：玩家对有四张手牌的目标使用过河拆桥，弹框直接展示四张牌的正面和点数，标题只写“选择一张牌”。
- 规则核对：Core 的决策者和卡牌所属区域是正确的——决策者为出牌者，可选牌全部来自目标区域；错误只在浏览器呈现。
- 根因：通用选牌框没有目标手牌的隐藏展示模式，也没有说明卡牌所属区域。
- 修复：目标手牌显示为可点击牌背并标注“手牌（未知）”；装备区和判定区仍正面显示；标题包含目标武将和“目标区域”。选择后只消耗已打出的过河拆桥，不追加己方支付。
- 回归：`过河拆桥只选择目标区域，目标手牌保持隐藏且不追加己方支付`。

### DG-08：Core 以 20ms 推进，仁德和出牌动画串到后续回合

- 严重级别：High
- 复现：AI 刘备仁德给予的牌仍在执行 500ms 入手动画时，Core 已继续执行后续动作甚至进入玩家出牌阶段；出牌动画还会固定停留 900ms，与下一张牌重叠。
- 根因：适配器所有命令都以固定 20ms 继续；每个无实际手牌变化的命令还会重排所有玩家手牌，持续堆积 jQuery 动画队列。
- 修复：删除固定毫秒数视觉屏障，领域事件监听器直接返回原生动画 Promise，Core 等待真正完成后再推进；只同步发生过手牌区移动的玩家；重排前取消同元素旧动画。
- 回归：`刘备仁德牌先完成入手动画，Core 才继续推进后续行动`。

### DG-09：浏览器回归只覆盖默认 33 名武将，未覆盖全部 49 名

- 严重级别：Medium
- 复现：默认浏览器启动仅启用标准包和风包，原有 UI 测试实际只构造了 33 名武将；49 名武将的数字来自非浏览器逻辑矩阵。
- 修复：新增真实 Chromium 全包场景，显式启用风、火、林、军争，逐一构造 43 张牌、49 名武将和 4 种身份的 8428 个组合，同时验证 Core 内容注册和全部卡牌/武将素材可加载。
- 回归：`浏览器构造全部 43 张卡牌、49 名武将和 4 种身份组合`。

## 动画架构改进

- 新增原生 Web Animations API 运行时，所有玩法动画通过 `Animation.finished` 返回可等待 Promise。
- 生产路径中的 jQuery `.animate()`、`.fadeIn()`、`.fadeOut()`、`.delay()`、`.stop()`、`$.fx` 和 `:animated` 已清零。
- 测试改用显式原生即时动画模式，不再修改 `jQuery.fx.off`。
- 首次发牌也进入同一动画屏障；四名角色发牌完成前 Core event log 保持为零。
- 装备牌使用独立装备动画，不再与通用出牌动画竞争同一个卡牌 DOM。
- 游戏快照恢复会统一取消原生动画和延迟任务，旧序列不会继续操作新页面。

## 玩家路径回归

本轮在浏览器中实际完成了以下交互：

1. 选择扩展、AI 难度和武将并开始游戏。
2. 经过 AI 回合进入真人出牌阶段。
3. 使用无中生有、火攻、雷杀、铁索连环。
4. 完成火攻展示与同花色弃牌、闪响应、无懈窗口和多目标结算。
5. 完成手牌超上限弃牌并进入下一回合。
6. 装备诸葛连弩并在同一回合连续使用两张杀。
7. 验证仁德给予后的手牌区同步。
8. 每个关键节点比较 Core state、Legacy player model 与可见 DOM 手牌；修复后三者一致。
9. 全程检查浏览器未捕获异常；最终回归未发现 JavaScript 页面错误。
10. 真实操作过河拆桥，确认目标手牌以牌背显示，选择后 Core、玩家模型和手牌 DOM 均为 3 张。
11. 开启真实 500ms 动画触发仁德，确认赠牌 DOM 先进入玩家手牌区，Core 才继续刘备的下一次行动。
